## 3. Engine behaviour contracts

### 3.1 `derive_monitoring` (`disaggregation/configuration.py:158-193`)

New shape:

```python
def derive_monitoring(device, graph, *, topology=None, declared=MonitoringLevel.UNKNOWN):
    if declared != MonitoringLevel.UNKNOWN:
        return declared                      # SHARED / HOME_TOTAL_ONLY / UNMONITORED
    if device is None or graph is None:
        return MonitoringLevel.UNKNOWN
    rows = set(graph.attribution_ct_ids(device.device_id))
    if not rows:
        return MonitoringLevel.HOME_TOTAL_ONLY
    return MonitoringLevel.SHARED
```

The docstring's claim that "`DEDICATED` means one thing" is deleted along with the branch.

### 3.2 Stored declarations

`effective_config` (`configuration.py:345-350`) currently does:

```python
declared = MonitoringLevel.UNKNOWN
try:
    declared = MonitoringLevel(str(metadata.get(MONITORING_KEY, "unknown")))
except ValueError:
    declared = MonitoringLevel.UNKNOWN
```

This already tolerates a removed value **at the topology-metadata layer**. It is not sufficient on its own: `load_device_configurations` (`storage/database.py:371-374`) validates the whole `DeviceConfiguration` payload and silently drops the row if `monitoring` is not a valid enum member. That is why task-01 step D migrates stored configuration payloads first.

Keep the try/except and add a regression test asserting a stored `"dedicated"` declaration resolves to `UNKNOWN` and then derives `SHARED` or `HOME_TOTAL_ONLY` from the graph — never raises, never fabricates a direct capability.

### 3.3 Attribution

`attribution_ct_ids` (`topology.py:417-426`): delete the dedicated fast-path; always use `most_specific_branch_group`. The function keeps its name and signature.

### 3.4 Solver

`_infer_device` (`engine.py:1423`) loses:
- parameter `direct`
- local `direct_is_ours` (`:1461`)
- the Level-1 block (`:1510-1588`, not `:1510-1580` — the return expression ends at `:1588`)
- the `direct` plumbing in `disaggregate` (`:705-712`)

`_reconcile` (`engine.py:2072-2085`) drops `direct_w` and the `DIRECT_MEASURED` sum; `accounted` becomes `inferred + model + prior`.

`_solve_system` (`engine.py:1036-1054`) no longer subtracts direct readings from `y` and no longer excludes directly-measured devices; remove the `direct` argument.

Tier/confidence code keeps its `Source.DIRECT_MEASURED` branches (`tiers.py:158-174`, `confidence.py:184-190`) as unreachable-but-harmless history: the enum member stays so old rows validate. Do not delete them, and do not leave user-visible strings that name the removed concept (see task-08 for `integration.py`'s availability flag and the tier-reason wording).

**`TIER_4_VERIFIED` is deliberately left intact and deliberately unreachable.** It stays defined and is *not* re-gated onto another source: `tiers.py:159` reaches it only from `Source.DIRECT_MEASURED`, and nothing produces that source any more. Historical inference rows carrying `direct_measured` still validate against the contract and still render as tier 4, so deleting the tier or rewriting its gate would break the reading of history for no gain. New results simply cannot reach it. Any test that previously asserted a declared load signal promoted a result to tier 4 must assert `TIER_3_MEASURED` instead, with a comment recording *why* — that is the highest tier a new result can reach.

## 6. Storage and migration contracts

### 6.1 Schema v11 (`storage/migrations.py`)

`LATEST_VERSION` 10 → 11. One SQL statement plus an `apply=` callback covering five surfaces:

1. `UPDATE ct_channels SET ct_type = 'branch' WHERE ct_type = 'dedicated_device';`
2. Device rows: union `dedicated_ct_ids_json` into `branch_ct_ids_json`, empty the former.
3. `metadata_json.projected_ct_ids`: strip ids that were in the old dedicated list **unless** a surviving device configuration still names them in `monitored_by_ct_ids`. The channel wizard never writes `projected_ct_ids` (`flow_logic.py:807-931`), so this cannot strip a user declaration made there.
4. `device_configurations.payload_json`: `"monitoring": "dedicated"` → `"shared"`, so the row is not silently dropped by `load_device_configurations` (`database.py:371-374`).
5. `inference_results.monitoring_level`: `'dedicated'` → `'shared'`, so historical rows validate against the narrowed enum.

Do **not** insert a `topology_versions` row: the returned version is the AUTOINCREMENT rowid (`database.py:242-248`), and a migration must not fake a client-visible bump. Historical `payload_json` blobs retain the old vocabulary; the engine never parses them, but `tools/audit/replay_capture.py:207` and `tools/dev/replay_nesting.py:68` do — record this as a known limitation in the release notes rather than rewriting history.

### 6.2 HA config-entry migration

`custom_components/wattmosaic/__init__.py` gains `async_migrate_entry(entry)`:
