# T05: recorder coverage probe

**Wave:** 1 · **Depends on:** none · **Owner:** none existing
**New files:** `tools/audit/check_recorder_coverage.py`, `tests/unit/test_recorder_coverage.py`

## Objective

Give the operator a one-command answer to "does HA's recorder actually hold my CT
entities for the last N days?" This detects the recorder-exclusion caveat (`design.md` §5)
before anyone relies on HA history (`interfaces.md` §7).

## Context

- Use `tools/audit/ha_client.py` (`HAClient.from_env()`, `fetch_history(client, ids,
  start=, end=, minimal=True)`). **Do not edit `ha_client.py`**; T04 may.
- The CT entity ids come from the latest `topology_versions` payload: `channels[].entity_id`
  where `ct_id` is set. Copy that read-only query pattern (`sqlite3.connect(f"file:{p}?mode=ro",
  uri=True)`) from `tools/audit/replay_capture.py:833-860`. Do not import from
  `replay_capture.py`, which T04 is editing.
- HA compressed rows: state `"s"`, timestamp `"lu"`, else `"lc"` (epoch seconds). See
  `tools/audit/derive_state_entities.py:270-310`.
- Fetch in 1-hour chunks so a 10-day window at 1 Hz doesn't produce one huge response.
  Only counts and timestamps are kept, never the values, so memory stays small.
- This tool is read-only toward HA. No service calls.

## Steps

1. Implement `EntityCoverage` and `coverage_report(...)` exactly as specified in
   `interfaces.md` §7 (pure function over a payload).
   - `max_gap_s`: largest gap between consecutive row timestamps, including the gap from
     the last row to `end`. HA writes no row while a value is unchanged, so a long gap is
     information, not an error. Report it but don't change status because of it.
2. Streaming variant for the CLI: fetch per chunk and fold each chunk into running
   per-entity counters (rows, first, last, previous timestamp, max gap). The pure function
   and the fold must produce identical results; test that.
3. CLI: `--db PATH` or `--entities ID [ID…]` (one is required); `--days FLOAT` (default 10);
   `--end ISO` (default now); `--json` (machine output). The default output is a table
   with a summary line, e.g. `12 ok · 1 short · 2 missing`. Exit 1 if any `missing`, else 0.
   Print a hint for `missing`: "excluded from the recorder? set raw_capture_days to capture
   locally".
4. Module docstring with usage. Add the file to nothing else. It is discovered by path.

## Tests (`tests/unit/test_recorder_coverage.py`, no network)

- `test_ok_entity`: rows spanning the window → `ok`, correct rows/first/last.
- `test_missing_entity`: requested entity absent from the payload or `[]` → `missing`.
- `test_short_entity`: first row 2 days after `start` → `short`.
- `test_lc_fallback_timestamp`.
- `test_max_gap_includes_tail_to_end`.
- `test_streaming_fold_matches_pure_report`: a payload split into chunks gives the same
  `EntityCoverage` list as the one-shot call.
- `test_entities_from_topology_db`: create a temp SQLite DB with a minimal
  `topology_versions(payload_json, version)` table and two channels → returns their entity ids.
- `test_cli_exit_code`: patch the fetch layer to return a canned payload with one missing
  entity → `main()` returns 1. With all ok → 0.
