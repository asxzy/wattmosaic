# T02: `capture` retention tier and `prune(capture_days=…)`

**Wave:** 1 · **Depends on:** none
**Owner:** `engine/wattmosaic_engine/storage/tiers.py`, `storage/repositories/aggregates.py`,
`storage/database.py` (the `prune` wrapper only), `tests/unit/test_storage_config.py`
(the `ct_samples` tier assertion at `:183` only)
**New file:** `tests/unit/test_capture_prune.py`

## Objective

Give `ct_samples` its own retention tier, so the on-loop `prune` can hand it to the
background purge (`interfaces.md` §2, `design.md` §3.2).

## Context

- `tiers.py:227-228` defines `RAW_HORIZON`/`AGGREGATE_HORIZON`. `prunable_tables()` at
  `:250-270` lists `("ct_samples", "received_at", RAW_HORIZON)` at `:258`.
- `AggregatesRepository.prune(raw_days, aggregate_days)` (`repositories/aggregates.py:80-117`)
  picks `agg_cutoff` if the horizon is `AGGREGATE_HORIZON` and `raw_cutoff` otherwise.
  Every registered table it does not delete is reported with 0.
- `Database.prune` (`storage/database.py:~420-435`) is a thin wrapper. The runtime calls it
  from `_maintenance_loop` at `core/runtime.py:2402`. **Do not edit runtime.py**; T08 owns it.
- Existing callers that must keep working unchanged, with no `capture_days` passed:
  `tests/unit/test_inference_records.py:325-328`, `tests/unit/test_contracts.py:223`,
  `tests/end_to_end/test_storage_e2e.py:377`. All expect `removed["ct_samples"] == 1` on
  the raw horizon.
- `tests/unit/test_storage_config.py:183` asserts
  `declared["ct_samples"] == ("received_at", RAW_HORIZON)`. Change it to `CAPTURE_HORIZON`
  and import the new constant. This is a deliberate semantic change (ADR-0042), not a
  weakening. Say so in the commit body.
- `tiers.py:877` defines `RAW_RETENTION_ENV`. Add `RAW_CAPTURE_ENV = "WM_RAW_CAPTURE_DAYS"`
  beside it.
- Check `storage_health_section` and any other consumer of `prunable_tables()` or the
  horizon strings (`grep -rn "RAW_HORIZON\|AGGREGATE_HORIZON\|prunable_tables" engine`).
  Each must handle the new value. If one maps horizons to day values, map
  `CAPTURE_HORIZON` sensibly (it is the capture horizon, not raw) and list what you changed.

## Steps

1. `tiers.py`: add `CAPTURE_HORIZON = "capture"` and `RAW_CAPTURE_ENV`, and export both.
   Switch the `ct_samples` entry to `CAPTURE_HORIZON`. Update the docstrings and comments
   that say `ct_samples` uses the raw horizon (`:50`, `:75`, `:223`, `:248`).
2. `aggregates.py` `prune`: add keyword-only `capture_days: int | None = None`.
   - `None`: `CAPTURE_HORIZON` tables use `raw_cutoff` (legacy).
   - Not `None`: skip `CAPTURE_HORIZON` tables. They are then reported as 0 by the
     existing "every registered table not deleted" loop.
   - Update the docstring.
3. `database.py` `prune`: forward `capture_days` with the same default.
4. Fix any other consumer found in the grep above.

`tests/unit/test_inference_records.py` `_reading` for a helper shape) with old and new

  rows survive and `removed["ct_samples"] == 0`.

  is still removed on the raw horizon.

- `test_raw_capture_env_name`.
