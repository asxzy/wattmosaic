## Objective

Record the decision and document the new setting, the changed retention semantics and how
to debug production with HA history.

## Steps

1. **ADR-0042** in `docs/decisions/README.md`, appended after ADR-0041 (`:2185`) in the
   same format (`## ADR-0042 — …`, Status, Context, Decision, Consequences). Also add it
   to any index table at the top of the file. Content:
   - *Context:* `ct_samples` is about 0.71 of the 0.81 GB/day growth (TODO §1). No
     production path reads it (README §"What this is", points 1–2). HA's recorder holds the
     same `state_changed` stream with a 10-day default.
   - *Decision:* raw CT capture is a debug option (`raw_capture_days`, default 0). The HA
     recorder is the production raw history. `ct_samples` has its own `capture` tier and is
     deleted only by a batched background job. Engine code never reads HA history; replay
     from HA history is a `tools/` feature. Amends DEC-30's raw-sample clause; the
     `event_evidence.samples_json` horizon is unchanged.
   - *Consequences:* the three caveats in `design.md` §5; the legacy rows drain on upgrade;
     the file does not shrink without a manual `VACUUM`.
