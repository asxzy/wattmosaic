**Wave:** 1 · **Depends on:** none (codes against the env name in `interfaces.md` §6)

## Objective

Expose the capture setting to HA OS App users, default off.

## Context

- `addon/config.yaml`: the header comment maps options to env vars (`:17-20`), `options:`
  holds the defaults (`:120-126`) and `schema:` the bounds (`:149-152`).
- `addon/run.sh:51-54`: mapping lines of the form `option|ENV_VAR|default`. Read how the
  loop treats an empty default versus `0`, and make sure `0` is exported as `0`, not
  dropped. If the loop skips falsy values, report it rather than redesigning the loop.
- `.env.example:18` has `WM_RETENTION_DAYS_RAW=30`. That is stale against the engine
  default of 7, but leave it unless the line is next to your edit; note it in your handoff.
- `tests/unit/test_derived_retention.py:398-414` holds the parity tests for
  `retention_days_raw`. **Do not add the equivalent tests for `raw_capture_days` here.**
  They import `RAW_CAPTURE_DAYS_RANGE` from T01's code, which is not merged yet. T10 adds
  them.

## Steps

1. `config.yaml`:
   - header line `#   raw_capture_days       -> WM_RAW_CAPTURE_DAYS (0 = off; HA recorder is the history)`;
   - `options.raw_capture_days: 0`, placed after `retention_days_versions`, with a one-line
     comment: "Debug only: days of full-rate CT readings kept locally. 0 = off.";
   - `schema.raw_capture_days: "int(0,90)"`.
2. `run.sh`: add `raw_capture_days|WM_RAW_CAPTURE_DAYS|0` next to the retention lines.
3. `addon/README.md`: if it documents options, add a row with the same wording, and say
   that HA's recorder (`purge_keep_days`, default 10) is the production history.
4. `.env.example`: add a commented block:
   ```
   # Debug only: days of full-rate CT readings kept in the engine DB (0 = off).
   # Production history comes from the Home Assistant recorder.
   WM_RAW_CAPTURE_DAYS=0
   ```
