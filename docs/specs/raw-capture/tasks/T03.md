# T03: batched `ct_samples` purge

**Wave:** 1 · **Depends on:** none · **Owner:** none existing
**New files:** `engine/wattmosaic_engine/storage/capture.py`, `tests/unit/test_capture_purge.py`

## Objective

Provide a pure storage function that deletes `ct_samples` rows in bounded,
independently committed batches, so the runtime can drain gigabytes of legacy rows without
stalling writers or building one huge WAL transaction (`interfaces.md` §3, `design.md` §3.2).

## Context

- An upgraded install may hold about 5 GB of `ct_samples` (7 days at about 0.71 GB/day).
- Indexes: `idx_ct_samples_time ON ct_samples(received_at)` and
  `idx_ct_samples_ct_time ON ct_samples(ct_id, received_at)`
  (`storage/migrations/legacy.py:301-302`). `id` is the integer primary key, and rows are
  appended in time order.
- Timestamp encoding: use `iso()` from `engine/wattmosaic_engine/storage/repositories/__init__.py:45`
  for `cutoff`, the same encoding `AggregatesRepository.prune` compares against.
- Single-writer seam: callers pass `db._conn` and `db._lock`, as `_prune_evidence` does
  (`core/runtime.py:2322`). Acquire the lock **per batch** and release it between batches so
  the writer loop can interleave.
- Migration rules don't apply (this is not a migration), but do not run `VACUUM` or any
  other auto-committing statement.
- Dependency direction: `storage/` must not import `core/`, `realtime/` or `inference/`.

## Design

```python
def purge_ct_samples(conn, lock, *, cutoff, batch_rows=5000, max_batches=20,
                     time_budget_s=2.0, monotonic=time.monotonic) -> PurgeResult
```

Per batch:

```sql
BEGIN IMMEDIATE;
DELETE FROM ct_samples WHERE id IN (
  SELECT id FROM ct_samples
  WHERE received_at < :cutoff          -- omit the WHERE when cutoff is None
  ORDER BY id LIMIT :batch_rows);
COMMIT;
```

Use `cursor.rowcount` for the count. Stop when:
- `rowcount < batch_rows`: `done=True`;
- `batches == max_batches` or `monotonic() - start >= time_budget_s`: `done=False`.

On exception: `ROLLBACK`, release the lock, re-raise (the caller turns it into a degraded
state). Missing table (`sqlite3.OperationalError` "no such table"): return
`PurgeResult(0, 0, True)`.

Validate arguments: `batch_rows >= 1`; `max_batches` is `None` or `>= 1`.

## Tests (`tests/unit/test_capture_purge.py`)

Use a real `Database(tmp_path / "x.db")` so the real schema and indexes exist, and insert
through `db.repos.samples.insert_readings`.

- `test_purge_all_when_cutoff_none`: 12 rows, `batch_rows=5`, `max_batches=None` →
  deleted 12, batches 3, done True, table empty.
- `test_purge_respects_cutoff`: old and new rows, cutoff between them → only old deleted.
- `test_purge_stops_at_max_batches`: 12 rows, `batch_rows=5`, `max_batches=1` →
  deleted 5, done False; a second call continues.
- `test_purge_stops_at_time_budget`: inject a fake `monotonic` that advances 10 s per call,
  `time_budget_s=1` → exactly one batch.
- `test_each_batch_commits`: after a run stopped by `max_batches`, a fresh connection sees
  the reduced count (proves the commit happened, not one open transaction).
- `test_lock_released_between_batches`: a lock wrapper that records acquire/release order
  shows strictly alternating acquire→release per batch.
- `test_missing_table_is_noop`: a bare sqlite connection without the table.
- `test_rollback_on_error`: force an error mid-batch (e.g. a connection wrapper that raises
  on `COMMIT`); the row count is unchanged and the lock is released.
- `test_rejects_bad_arguments`.
