## Objective

Prove the integrated change meets every acceptance criterion in `design.md` §4, add the
cross-unit tests that couldn't exist in Wave 1, and record measured disk growth.

## Steps

1. **Parity tests** (`tests/unit/test_raw_capture_parity.py`), mirroring
   `tests/unit/test_derived_retention.py:398-414`:
   - `test_addon_and_engine_capture_bounds_match`: `schema.raw_capture_days` `int(a,b)` ==
     `RAW_CAPTURE_DAYS_RANGE`;
   - `test_addon_capture_default_matches_engine`: `options.raw_capture_days ==
     EngineConfig().raw_capture_days == 0`, and `"raw_capture_days|WM_RAW_CAPTURE_DAYS|0"`
     is in `run.sh`;
   - `test_tier_env_name_matches_settings`: `tiers.RAW_CAPTURE_ENV == "WM_RAW_CAPTURE_DAYS"`
     and the settings loader reads that name (set the env and observe the field).
2. **No hidden reader.** Re-run the search and record the result in `verification.md`:
   ```bash
   grep -rnE "ct_samples|repos\.samples\.(readings_between|ct_samples_between|latest_|sample_exists)" \
     engine/wattmosaic_engine addon/ui custom_components | grep -v migrations/
   ```
   Every hit must be a write path, the purge, the tier registry or a docstring. Any read
   path → stop and report.
3. **All CI gates** from `CLAUDE.md` § Commands on Python 3.11 and 3.12 (use `uv` or
   two venvs). Paste the outputs into `verification.md`.
4. **Perf numbers.** `tools/dev/perf_runtime.py --quick` twice: default config, and
   `WM_RAW_CAPTURE_DAYS=7`. Check how `perf_runtime.py` builds `EngineConfig` (`:92`); if
   it doesn't read env, set the field the way the tool already sets others, and note it.
   Record `db_growth_bytes_per_day` and `db_growth_by_table_bytes_per_day["ct_samples"]` for
   both runs in `verification.md` and in TODO §1. Expected: `ct_samples` ≈ 0 with the default.
5. **Upgrade drain rehearsal.** On a copy of a DB with legacy `ct_samples` rows (synthesize
   with `tools/dev/rehearse_migration.py --synthesize`, or insert about 100k rows through
   the repository), start a real `EngineCore` with the default config, run the maintenance
   tick or `_purge_raw_capture` until done, and record rows before and after, the number of
   batches and the longest single batch duration. Assert that no batch exceeded the time
   budget by more than one batch.
6. **Operator-run items** (list them in `verification.md` and do not run them; they need a
   live HA):
   - `tools/audit/check_recorder_coverage.py --db <prod copy>`;
   - `tools/audit/replay_capture.py --ha-history --db <prod copy> --minutes 60`.
7. **Docs closure.** Tick TODO §1's first box, adding the measured numbers. Append a dated
   entry to `PROJECT_STATUS.md` (append-only) summarising the change and pointing to ADR-0042.
