## Objective

Show at a glance whether the engine keeps raw CT readings, so a support conversation
starts from "use HA history" or "use the local capture" (`interfaces.md` §5, `design.md` §3.3).

## Context

- `health()` at `core/diagnostics_api.py:47` returns `HealthResponse(..., details={...})`
  (`:95`). `details` is documented as additive and schema-free, so an older integration
  keeps parsing. **No contract change** and no `CONTRACT_VERSION` bump.
- `diagnostics/report.py:266-274` builds `engine_health` from a fixed key list taken from
  `_health_section(core_health, …)`. Check that `_health_section` keeps `details`. If it
  drops it, read `raw_capture` from `core_health` the same way the other keys are read.
- The panel (`addon/ui/view-diagnostics.js:39-60`) reads `report.engine_health` and renders
  `kv([...])` rows in the Engine card. The panel is a vanilla ES module with no inline
  script or style and no external origins. `tools/dev/check_panel.py` gates it.
- Do **not** reference `raw_capture_purged` (owned by T08).

## Steps

1. `diagnostics_api.py` `health()`: add
   `"raw_capture": {"days": int(self.config.raw_capture_days), "enabled": self.config.raw_capture_days > 0}`
   to `details`.
2. `report.py`: `engine_health["raw_capture"]` = that dict, or `None` when unavailable.
3. `view-diagnostics.js`: one row in the Engine card `kv`:
   `['Raw CT capture', rawCaptureText(health.raw_capture)]` with a small module-local helper:
   - `null`/`undefined` → `'—'`;
   - `enabled: false` → `'Off (history comes from the Home Assistant recorder)'`;
   - `enabled: true` → `` `On, keeping ${days} day${days === 1 ? '' : 's'}` ``.
