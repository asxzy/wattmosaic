# D5 — Retention, tiers and storage health for the new tables

**Wave:** 5 · **Depends on:** S16, P4 · **Size:** S · **Decisions:** DEC-30 · **Analysis:** `analysis/A-…` C11, WP-A7

## Objective
- Apply DEC-30 retention: evidence 400 days, raw window samples 30 days, versions and matrix history forever.
- Re-tier `device_events` against the new `ha_events_v3`/`event_evidence`.
- Make sure pruning never deletes evidence that replay still needs.
- Surface the storage health of the new tables.

## Owns
- `engine/wattmosaic_engine/storage/tiers.py` (prune declarations)
- `engine/wattmosaic_engine/core/diagnostics_api.py` (from X03)
- `engine/wattmosaic_engine/diagnostics/report.py`
- new `tests/unit/test_retention_v3.py`

## Steps
1. Prune rules:
   - raw samples inside `event_evidence.samples` are thinned to summary statistics after 30 days, and the Δ, baseline, σ and quality are kept;
   - evidence rows are deleted after 400 days only if no active derived run references them.
2. `device_events` stops receiving writes once P6 switches to `ha_events_v3`. It stays read-only until Z1 renames it.
3. Storage health: per-table row counts, growth per day, and the oldest row, for every new table.
4. Add `mapping_version_id` to `/status` (requested by M3).

## Tests
- Prune never deletes L4 versions or matrix history.
- Thinning keeps Δ/σ/baseline, and a replay (L7) still reproduces the result.
- A referenced evidence row is not deleted.
- Storage health lists every table registered in `TIERS`.
