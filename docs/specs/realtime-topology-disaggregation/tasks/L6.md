# L6 — Background learner worker off the event loop

**Wave:** 4 · **Depends on:** L5, X03 · **Size:** S · **Decisions:** DEC-37 · **Analysis:** `analysis/F-…` C7, WP-F6; `analysis/B-…` C2

## Objective
Training, validation, promotion and the registry swap run on the background executor, driven by a per-subject dirty set. Today they run inline in the 5 s inference call on the asyncio loop (`integration.py:361-363`, `main.py:1268`).

## Owns
- new `engine/wattmosaic_engine/learning/worker.py`
- `engine/wattmosaic_engine/backend/learning.py` (from X03)
- new `tests/integration/test_training_off_loop.py`

## Steps
1. `LearningWorker.submit(observation_ids)` updates the dirty set. Jobs are chunked to ≤ 2 s of CPU each. Results go to `Registry.activate` (atomic swap).
2. Restart safety: on start, the dirty set is re-derived from S18 `dirty_subjects()` (HB §15).
3. A cycle with no new confirmed evidence costs zero learning DB queries. This removes the scan of every topology device per cycle (`integration.py:690-700`).
4. P6 provides the executor and the submit hook. Until then, the worker can be driven directly in tests.

## Tests
- `/healthz` latency stays < 100 ms while a forced 2 s training runs (modelled on the ADR-0033 tests).
- No queries when nothing is dirty.
- A worker restart loses no work.
