# D4 — Inference snapshot assembly and provenance resolver

**Wave:** 4 · **Depends on:** S17, I5, D1 · **Size:** M · **Interfaces:** §6 `InferenceSnapshot`, §9 snapshot/devices/groups/provenance routes · **Analysis:** `analysis/A-…` C7, WP-A4

## Objective
- `/snapshot` serves a real HB §12.1 `InferenceSnapshot` built from the live pipeline. Today it is rebuilt from a lossy DB round-trip (`main.py:1554`).
- The snapshot is persisted only when its content changes.
- A provenance resolver answers the nine HB §18 questions for any estimate.

## Owns
- `engine/wattmosaic_engine/core/snapshot.py` (from X03)
- new `engine/wattmosaic_engine/provenance/__init__.py`, `provenance/resolver.py`
- new `engine/wattmosaic_engine/api/routes/snapshot_v3.py` (`/snapshot` v3, `/devices`, `/devices/{id}`, `/groups`, `/groups/{id}`, `/provenance/{kind}/{id}`); legacy routes are removed in Z1
- new `tests/integration/test_snapshot_v3.py`, `tests/unit/test_provenance_resolver.py`

## Steps
1. `SnapshotAssembler.on_result(result, held_readings, quality, residual_points) -> InferenceSnapshot`:
   - merge per subject, so the latest result wins per subject and per group;
   - produce `stale_sources` and `unresolved_events`;
   - persist via S17 `put_snapshot` (hash-deduplicated);
   - publish copy-on-write.
2. On restart, load `latest_snapshot()`; there is no hidden state (HB §15).
3. The resolver answers, for an estimate:
   - which reader measurements contributed (evidence → samples);
   - which event associations (groups, matches);
   - which model version;
   - which topology and mapping versions;
   - the status;
   - the identifiability;
   - the bounds;
   - `updated_at`.

   It returns a typed `ProvenanceAnswer`.

## Tests
- After a restart, the snapshot equals the pre-restart one.
- An unchanged state writes no new snapshot row.
- Every estimate's evidence refs resolve.
- All 9 questions are answered for an ESTIMATED, a MEASURED and a group member estimate.
- A group member has no individual value anywhere in the snapshot.
