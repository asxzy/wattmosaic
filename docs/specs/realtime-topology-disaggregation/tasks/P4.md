# P4 — Event window collector and immutable event evidence

**Wave:** 3 · **Depends on:** P3, S16 · **Size:** M · **Decisions:** DEC-18, DEC-30 · **Design:** §4 (window) · **Analysis:** `analysis/B-…` WP-B4

## Objective
For each detected step, capture the pre-window from the ring and keep the post-window open. Produce `EventEvidence`: PROVISIONAL at the first post-sample, FINAL at close, immutable afterwards. A late sample produces a superseding record.

## Owns
- new `engine/wattmosaic_engine/realtime/windows.py`
- new `tests/unit/test_windows.py`

## Steps
1. Per-load-class window configuration, resolved like `IsolationConfig` (`disaggregation/isolation.py:457-612`): global → class → device. Defaults: 30 s pre or ≥ 2 samples, 120 s post.
2. The evidence includes samples, Δ, baseline, σ (from P2, **not** from the pre-window), quality flags, `topology_version_id` and the window bounds. It is written through S16 `put_evidence` in batches, via the persist queue (`core/runtime.py` hook provided by P6; until then, a callback).
3. Late sample inside a FINAL window: create a new evidence id with `supersedes=<old id>` in metadata. The old record stays.
4. Expose `on_final(evidence)` and `on_provisional(evidence)` callbacks for P5.

## Tests
- The pre-window holds ≥ 2 samples at 15.7 s cadence, otherwise `insufficient_pre` is flagged.
- Immutability: re-putting the same id raises.
- A late sample creates a superseding record and leaves the old one byte-identical.
- Replay of Δ from stored evidence equals the live Δ after raw samples are pruned.
