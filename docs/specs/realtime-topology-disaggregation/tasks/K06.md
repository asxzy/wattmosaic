# K06 — Power-model contracts: spec union, versions, events, prediction, kernel, observation

**Wave:** 1 · **Depends on:** K00 · **Size:** M · **Decisions:** DEC-31–34 · **Interfaces:** §5 · **Analysis:** `analysis/F-power-models-learning.md` C1–C5

## Objective
A discriminated, fully serialisable power-model spec. This prevents DEF-02 by construction: there is no instance state outside the spec. It comes with append-only versions and a status-event log, a prediction type that can say "unknown", and deterministic learning observations.

## Owns
- `engine/wattmosaic_engine/contracts/power_models.py`
- its generated schemas
- new `tests/unit/test_contracts_power_models.py`

## Steps
1. Implement `interfaces.md` §5 contracts: `ModelBasis`, `ModelClass`, `LevelStat`, `FixedSpec`, `AdjustableSpec`, `DynamicSpec`, `KernelPhase`, `ResponseKernelSpec`, `ComponentSumSpec`, `PowerModelSpec` (discriminated on `kind`), `PowerModelVersion`, `PowerModelEvent`, `PredictionStatus`, `PowerPrediction`, `DeltaPrior`, `LearningObservation`.
2. Reuse the legacy `PowerLevel`. Note that OFF/IDLE/STANDBY must be distinct members; if the legacy enum collapses them, add a new `PowerLevelV3` here and document it.
3. Validators:
   - `PowerPrediction.status == UNKNOWN` ⇔ `mean_w is None`;
   - `AdjustableSpec` knots are sorted and the same length;
   - `basis == ABSOLUTE_ANCHOR` ⇒ `LearningObservation.level_w` may be set; otherwise it must be None;
   - `observation_id` is a deterministic hash helper.
4. `schema_version` starts at 1. Provide `SPEC_SCHEMA_VERSION`.

## Tests
- Round-trip of every spec kind via the discriminator.
- An unknown prediction keeps `None`.
- Observation id determinism.
- A spec with extra keys is rejected (`extra="forbid"`).
