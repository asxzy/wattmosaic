# X05 — Storage package: repositories, per-version migrations, pre-migration backup

**Wave:** 0 · **Depends on:** — · **Size:** L · **Decisions:** DEC-02 · **Analysis:** `analysis/A-…` §5 T1–T5, T8

## Objective
Let S13–S19 add migrations and DAOs in parallel without touching shared files, and add the automatic backup that DEC-02 requires.

## Owns
- `engine/wattmosaic_engine/storage/database.py`, which keeps the connection, locks, `_reader()`, `reset()`, prune dispatch, and thin delegation to repositories
- new `engine/wattmosaic_engine/storage/repositories/{__init__,samples,topology,devices,inference,records,models,learning,events,residual,associations,aggregates}.py`
- `engine/wattmosaic_engine/storage/migrations.py` → package `storage/migrations/` (`__init__.py`: `apply_migrations`, `current_version`, `LATEST_VERSION`, helpers; `legacy.py`: versions 1–11 verbatim)
- `engine/wattmosaic_engine/storage/tiers.py`
- `tests/unit/test_migrations.py`, `tests/unit/test_migration_matrix.py` (port only)
- new `tests/unit/test_migration_discovery.py`

## Steps
1. Discovery: modules named `vNNN_<slug>.py` export `MIGRATION: Migration` and `TIERS: dict[str, Tier]`. They are ordered by `NNN`. A duplicate number raises at import. A `v012_*` module is refused (12 is the payload-encoding marker, `migrations.py:791-800`).
2. `tiers.py` merges `TIER_TABLES` with every migration module's `TIERS`, so `test_every_table_is_classified` passes without later edits.
3. **Backup:** in `Database.__init__`, before `apply_migrations`, if a pending version ≥ 13 exists:
   - checkpoint the WAL;
   - copy the file to `<db>.pre-v<NNN>.<UTC timestamp>.bak`, reusing the steps from `reset()` (`database.py:182`);
   - log the path;
   - keep the newest 3 backups.
4. Repositories: move SQL methods verbatim. `Database` keeps delegating methods with the old names, so no caller changes in Wave 0.

## Traps
- Each migration runs in `BEGIN IMMEDIATE`, with `PRAGMA user_version` set inside the transaction. Never `VACUUM` inside one.
- `PRAGMA foreign_keys=ON` plus the `ct_channels.parent_ct_id` self-reference is why `_insertion_order` exists (`database.py:279-309`). Keep it.
