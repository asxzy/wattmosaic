# P3 — Streaming change detector with identity, hysteresis and CUSUM

**Wave:** 3 · **Depends on:** P2 · **Size:** M · **Design:** §3 (detector) · **Analysis:** `analysis/B-…` C4

## Objective
A per-reader state machine (STABLE → SUSPECT → CONFIRMED_STEP / TRANSIENT_REJECTED / DRIFT). It emits **exactly one** `MeasurementEvent` per physical step, with signed Δ, onset bounds, a step class and a quality score. There is no global watt threshold.

## Owns
- new `engine/wattmosaic_engine/realtime/detection.py`
- `engine/wattmosaic_engine/disaggregation/events.py` (keep `detect_step` for confirmation and offline use; do not delete `StepTracker` until Z2)
- new `tests/unit/test_detection.py`

## Steps
1. Implement design §3 "Detector" with every parameter configurable (a `DetectorConfig` dataclass). `detector_version` is a constant string, part of the event id.
2. Use `ReaderStateStore.freeze_baseline` on entering SUSPECT. Release it on STABLE or after confirmation plus settling.
3. Emit `MeasurementEvent`s to a callback. Emit `DATA_GAP` quality events when a reader goes missing.
4. Primed values never open SUSPECT.

## Tests
- Positive and negative steps.
- Sustained vs transient.
- **One step yields exactly one event**, even when 20 identical samples follow.
- False-alarm rate < 1 per reader-day on 7 simulated days of Gaussian plus heavy-tail noise with no steps.
- A 10 W step is detected on a quiet reader (σ = 1 W) and not on a noisy one (σ = 8 W).
- Drift over 3 h is classified DRIFT, not events.
- A periodic tag on an X07 fridge cycle.
- A steady 3 W standby produces no events.
- Onset bounds include the true onset in 100 % of X07 cases with a window-averaged reader.
