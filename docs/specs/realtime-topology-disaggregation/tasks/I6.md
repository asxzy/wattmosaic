# I6 — Match lifecycle and versioned event inference records

**Wave:** 4 · **Depends on:** I1, I5, S16 · **Size:** M · **Decisions:** DEC-15 · **Design:** §7 (match lifecycle) · **Analysis:** `analysis/D-…` §1 rows §7.6/§12.2/§12.3, WP-D7 · **Closes:** AT-18

## Objective
- A stateful-but-injected match store for the HB §7.6 lifecycle.
- `EventInferenceRecord`s whose interpretation is versioned (initial, late data, window closed, model update, topology update, replay) while evidence stays immutable.
- Read APIs for events and per-device records.

## Owns
- new `engine/wattmosaic_engine/inference/matching.py`, `inference/records.py`
- new `engine/wattmosaic_engine/api/routes/events.py` (`GET /events`, `GET /events/{group_id}`, `GET /devices/{id}/records`; the legacy records handler is removed in Z1)
- new `tests/unit/test_matching.py`, `tests/unit/test_records.py`
- `tests/acceptance/test_at18_late_revision.py` (remove xfail)

## Steps
1. `MatchStore` per K08: an immutable snapshot plus `apply(delta)`, persisted through S16 (records) and a small `match_state` JSON on mapping cells (M2 reads it). Transition rules follow design §7.
2. `RecordWriter.write(result, reason)` appends a revision with `previous_record_id` and never edits.
3. Expiry runs as a background job (P6 executor) daily.

## Tests
- **AT-18:** revision 1 is PROVISIONAL from Main only. A Circuit A sample 20 s late gives revision 2, REVISED, with a changed attribution. Revision 1 and the evidence stay byte-identical.
- HB §7.6: 1 event gives PROVISIONAL; 5 consistent events give CONFIRMED; a contradiction gives CONFLICTED; history stays traceable.
- The unknown candidate's state is persisted per group (AT-10 support).
- Replay with a new model version appends a `replay` revision (AT-19 support).
