# T4 — Topology service: declared edges, per-edge confirm/reject, candidate versions, API

**Wave:** 3 · **Depends on:** S14, D1, X04 · **Size:** M · **Decisions:** DEC-10, 11, 13 · **Interfaces:** §9 topology routes · **Analysis:** `analysis/C-…` C4, WP-C2

## Objective
Replace destructive `PUT /topology` (DELETE plus re-insert, `storage/database.py:311-361`) and blanket `POST /topology/confirm` (`main.py:1824-1840`) with event-sourced, per-edge operations. Every change records a `ConfigurationEvent` and a candidate version that goes through `VersionService`.

- `engine/wattmosaic_engine/core/topology_api.py` (from X03)
- new `engine/wattmosaic_engine/api/routes/topology_v3.py`
- new `tests/integration/test_topology_v3_api.py`
- `engine/wattmosaic_engine/api/routes/topology.py` (from X04): leave the legacy handlers in place; Z1 deletes them

## Steps
1. `POST /topology/edges` takes `{relation, source, target, declared_by: "user"}`. It:
   - validates via T1;
   - records a DECLARED `ConfigurationEvent`;
   - proposes a version and promotes it immediately (a user declaration is authoritative, DEC-10).

   The response is the version id and the event id.
2. `POST /topology/edges/{id}/pin` and `/reject` take user authority over an inferred edge. Reject moves it to REJECTED with `valid_until`.
3. `GET /topology` returns the active version, its edges (all lifecycles, filterable) and T1's `primary_display_tree`. `GET /topology/versions[/{id}]` returns history.
4. Endpoint config edits (phase, polarity, multiplier) append an `EndpointConfigRevision` (S13 repository) and record a DECLARED event. They never rewrite.
5. Learning gate replacement: provide `edges_confirmed_for(subject_id) -> bool` for L4. This replaces the aggregate `Topology.status == CONFIRMED` gate (`storage/database.py:380-385`, `analysis/C-…` T11).

## Tests
- A PUT-equivalent declaration never deletes rows: the edge history keeps the old edge with `valid_until`.
- Rejecting an inferred edge survives a re-run of inference (T5 respects REJECTED/pinned).
- `/topology` exposes PROVISIONAL edges as suggestions, so `/topology/nesting` is no longer needed.
- Versions chain through `parent_version_id`.
- A calibration edit creates a new revision and does not alter old samples.
