# T7 — Configuration change and self-healing workflow (HB §14)

**Wave:** 4 · **Depends on:** T4, T5, D1, M2 · **Size:** L · **Design:** §5 (self-healing) · **Analysis:** `analysis/C-…` §1 rows §14, WP-C7 · **Closes:** AT-15, AT-16

## Objective
Implement HB §14 steps 1–10 for both declared and **inferred** changes:
- CT reversed;
- calibration changed;
- plug or reader relocated;
- reader removed.

Mapping and topology are versioned and promoted. Reconciliation is enqueued. Power models are **never** touched.

## Steps
1. Inferred detectors (design §5). Each produces a SUSPECTED `ConfigurationEvent` through `VersionService.record_configuration_event`.
2. The workflow:
   - `mark_suspected` on affected edges and mapping edges, which makes M2 flip cells to SUSPECTED_CHANGE;
   - the confidence penalty is applied by M2 and I5 reading the lifecycle;
   - propose candidate versions;
   - collect evidence: T5 for topology, M2 match history for mapping;
   - promote when the candidate's evidence reaches the CONFIRMED threshold;
   - otherwise reject after 7 days and restore the lifecycles.
3. On promotion: enqueue L7 reconciliation for the affected time range and subjects. Write an audit entry.
4. Assert in code that the workflow never calls any `power_model` write API. Add a test that patches L1's repository to raise on write.

## Tests
- **AT-15:** the X07 plug move. The old mapping edge becomes RETIRED with `valid_until`; the new edge goes PROVISIONAL → CONFIRMED; the mapping version increments; the TV model version id is unchanged; old event groups still resolve with the old mapping version.
- **AT-16:** a CT polarity flip → SUSPECTED → affected cells SUSPECTED_CHANGE → new topology version after N events → the prior version is readable. A calibration change is not retroactive.
- A suspected change with no corroboration is rejected after the timeout, and its lifecycles are restored.
