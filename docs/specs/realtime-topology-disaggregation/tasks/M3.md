# M3 — Matrix API v2 and drill-down routes

**Wave:** 4 · **Depends on:** M2, X04 · **Size:** M · **Decisions:** DEC-28 · **Interfaces:** §9 matrix routes · **Analysis:** `analysis/E-…` WP-E3, trap T6

## Objective
Typed matrix endpoints read from the materialised view on a reader connection: ETag by mapping version, `at=` historical queries, filters and paging, plus cell, reader-column and row drill-downs (HB §19.4).

## Owns
- new `engine/wattmosaic_engine/mapping/service.py`
- `engine/wattmosaic_engine/core/mapping_api.py` (from X03)
- new `engine/wattmosaic_engine/api/routes/matrix.py`
- `engine/wattmosaic_engine/api/protocols.py`: the `MappingProvider` Protocol only
- new `tests/integration/test_matrix_api.py`

## Steps
1. `GET /matrix`:
   - `MatrixPayload`;
   - `ETag: <mapping_version_id>-<cells_hash>`, answering `304` on `If-None-Match`;
   - query params `at`, `panel`, `reader`, `room`, `row_kind`, `mapping_status`, `identifiability`, `visual`, `min_confidence`, `active_state`, `page`, `page_size`.
2. `GET /matrix/cells/{row_id}/{reader_id}`: the cell, its history, event groups (I6), evidence refs, confidence components, contradictions and uncertainty reasons.
3. `GET /matrix/readers/{id}`: scope, topology relations, measured total, known contributions, unknown, residual. Never a sum across readers.
4. `GET /matrix/rows/{id}`: operating state, power profile (L1), observed readers, mapping history.
5. Add `mapping_version_id` to `/status` so the panel can poll cheaply. This is coordinated with the D5 owner of `diagnostics_api.py`; it is a one-line addition requested through the orchestrator.
6. Leave `/mapping` in place until Z1.

## Tests
- Contract round-trip.
- `304` on an unchanged version.
- `at=` returns history.
- With a 500×100 synthetic matrix: p95 < 300 ms and a bounded query count (no N+1; assert the count with a sqlite trace).
- The reader drill-down shows residual = measured − Σ known − unknown.
- None survives JSON.
- No writer lock is taken.
