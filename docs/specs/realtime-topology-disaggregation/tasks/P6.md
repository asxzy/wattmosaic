# P6 — Three-loop runtime in EngineCore (fast, event, background)

**Wave:** 4 · **Depends on:** P5, I7, L6, M2, D4 · **Size:** L · **Decisions:** DEC-03, 14, 37 · **Design:** §10 · **Analysis:** `analysis/B-…` §0, C1, C2, WP-B6, traps 1, 7, 8

## Objective
Replace the 5 s full recompute with the three loops of HB §5. The fast path stays O(1) per sample, and inference and learning never run on the asyncio loop thread.

## Owns
- `engine/wattmosaic_engine/core/runtime.py` (from X03)
- `engine/wattmosaic_engine/config/settings.py`
- new `engine/wattmosaic_engine/core/executors.py`
- new `tests/integration/test_three_loop_runtime.py`, `tests/integration/test_healthz_latency_under_load.py`

## Steps
1. **Fast loop.** `on_state_changed` → P1 → P2 → P3 → P4/P5 bookkeeping, inline. No DB reads; writes go through the persist queue.
2. **Event loop.** An asyncio task awaits a `BoundedQueue` (`ingestion/queue.py`) of ready or revised groups. For each one:
   - build an immutable input bundle: operator from T2 for the current `VersionTriple`, model-set view, residual view, history, match store snapshot;
   - run `infer_group` in the single-thread inference executor;
   - then, in order: persist the record (I6/S16) → `MatrixUpdater.apply` (M2) → snapshot assembly and swap (D4, copy-on-write) → enqueue a learning job (L6) when the group is CONFIRMED.
3. **Steady pass.** A held-level change beyond 3σ on any reader triggers `infer_steady` for that operator component, debounced to once per cadence. A 60 s heartbeat publishes staleness only (DEC-14).
4. **Background executor** (one thread): it runs jobs submitted by L6, L7, T3, T5, T6, T7 and M2's reconciler, each chunked to ≤ 2 s (DEC-37).
5. Settings:
   - add `WM_EVENT_QUEUE_MAX`, `WM_STEADY_HEARTBEAT_S` (60), `WM_UNKNOWN_PENALTY_SCALE` (1.0), `WM_EVIDENCE_RETENTION_DAYS` (400), `WM_EVIDENCE_RAW_RETENTION_DAYS` (30);
   - `WM_INFERENCE_INTERVAL_S` is accepted, ignored, and logged as a warning (DEC-03).
6. Bind the X07 replay driver to `EngineCore` with the injected clock. This is what K07's `engine_harness` uses.
7. Metrics: loop lag, per-stage latency, queue depths, dropped groups. Add them to `/metrics` via the D5 diagnostics owner, or a new route module `api/routes/runtime_metrics.py` owned here.

## Tests
- `test_healthz_latency_under_load`: `/healthz` p99 < 100 ms while a synthetic 10 s background job runs and 30 HA events/s arrive.
- A flat stream (no steps) for 1 h simulated produces 0 `infer_group` calls and ≤ 60 heartbeats.
- An HA event plus a reader step produce a PROVISIONAL result within one cadence of the first post-sample.
- Kill and restart mid-group: the group is reconstructed from persisted evidence and the result is identical.
- The X07 HB §17 run completes, and K07's `engine_harness` no longer raises.

## Traps
- API handlers read engine state in worker threads (`api/server.py:622-628`). Publish only immutable snapshots.
- Writes stay single-writer (ADR-0004). Background jobs write through the persist queue or their own short transactions.
