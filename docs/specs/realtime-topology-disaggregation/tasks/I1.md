# I1 — Candidate generation and topology-aware filtering

**Wave:** 3 · **Depends on:** K04, K08 · **Size:** M · **Decisions:** DEC-17 · **Design:** §7 (candidates, filtering) · **Analysis:** `analysis/D-matching-joint-inference.md` §1 rows §7.1/§7.2/§7.5, C10, C11, WP-D2 · **Closes:** AT-10

## Objective
For an `EventGroup`, build the candidate set from all nine HB §7.1 sources, **always** including one `unknown_scope` candidate per affected reader scope. Filter by topology only on CONFIRMED incompatibility, and record every rejection with a reason.

## Owns
- new `engine/wattmosaic_engine/inference/__init__.py`, `inference/candidates.py`, `inference/topology_filter.py`
- new `tests/unit/test_candidates.py`
- `tests/acceptance/test_at10_unknown_alternative.py` (remove xfail)

## Steps
1. `generate_candidates(group, operator, models, mapping, unknown_profiles, groups, pending_delayed, ring) -> list[CandidateHypothesis]`. The nine sources:
   1. HA state sub-events;
   2. HA attribute sub-events;
   3. subjects with a learned profile whose `DeltaPrior` fits ±3σ;
   4. subjects with a mapping edge to any affected reader;
   5. plug steps;
   6. Unknown Load Profiles at affected scopes (T6 view; a fake until then);
   7. operator-visible subjects;
   8. subjects with a pending delayed response from an earlier group (kernel window still open);
   9. known device groups (I4 history).

   Merge the sources per subject.
2. Add `unknown_scope:<reader>` for each affected reader that is the deepest scope of a step.
3. Filter: reject only if every path from the subject to the affected readers crosses a CONFIRMED non-containing structure **and** the subject's mapping edge is CONFIRMED elsewhere. If the path is merely PROVISIONAL-incompatible, keep the candidate with a flag that I2 uses in term E.
4. Cap at 32 candidates, ranked by source count and then prior fit. Truncation is recorded on the result. The unknown candidates are never truncated.

## Tests
- **AT-10 (property test, hypothesis-based or seeded random groups):** every candidate set contains an unknown candidate for each affected scope.
- An X07 fridge step with no HA event → candidates {fridge profile (source 6), unknown_scope}.
- A provisional-incompatible candidate is kept and flagged; a confirmed-incompatible one is rejected with a reason.
- A delayed HVAC compressor from a group opened 90 s earlier is a candidate via source 8.
- Truncation is logged and never drops unknown.
