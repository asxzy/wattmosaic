# X01 — Split `contracts.py` into a package (no behaviour change)

**Wave:** 0 · **Depends on:** — · **Size:** M · **Analysis:** `analysis/A-domain-contracts-storage.md` §5 T1, T6, T7

## Objective
Turn `engine/wattmosaic_engine/contracts.py` (3 155 lines) into a package so that K00–K06 can each own one submodule. Behaviour, imports and generated schemas stay **byte-identical**.

## Owns
- `engine/wattmosaic_engine/contracts.py` → `engine/wattmosaic_engine/contracts/` (`__init__.py`, `legacy.py`, empty `foundation.py`, `entities.py`, `measurement.py`, `topology.py`, `inference.py`, `matrix.py`, `power_models.py`)
- `tools/dev/export_schemas.py`
- new `tests/unit/test_contracts_package.py`

## Steps
1. Move the file verbatim to `contracts/legacy.py`. `CONTRACT_VERSION` stays in `legacy.py` for now; Z1 moves it to `foundation.py`.
2. `contracts/__init__.py`:
   - `from .legacy import *` plus explicit re-export of private names that tests import (grep `from wattmosaic_engine.contracts import _`);
   - then `from .foundation import *`, `from .entities import *` … for the six new modules, each starting as `__all__: list[str] = []` and `SCHEMA_EXPORTS: list[tuple[str, type]] = []`.
   This facade must never need editing again (implementation-plan §4 rule 3).
3. `export_schemas.py`: keep the current `MODELS` list as the legacy export set. Additionally collect `SCHEMA_EXPORTS` from each new submodule. The output for the legacy set must be byte-identical.
4. Grep `tools/` and `tests/` for `contracts.py` path literals and point them at `contracts/legacy.py` or the package.
