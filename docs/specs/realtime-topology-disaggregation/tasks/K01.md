# K01 — Entity contracts: Physical Device, Load Component, HA Entity/Link, Measurement Endpoint

**Wave:** 1 · **Depends on:** K00 · **Size:** M · **Decisions:** DEC-04, 05, 07, 08 · **Interfaces:** §2 · **Analysis:** `analysis/A-…` §1.1, C1–C4, C10

## Objective
Implement HB §1's four separate object kinds and their many-to-many links.

## Owns
- `engine/wattmosaic_engine/contracts/entities.py`
- its generated schemas
- new `tests/unit/test_contracts_entities.py`

## Steps
1. Implement `interfaces.md` §2 exactly: `EndpointKind`, `EndpointScope`, `ScopeStatus`, `MeasurementEndpoint`, `EndpointConfigRevision`, `PhysicalDevice`, `LoadComponent`, `HaEntity`, `HaEntityLink`.
2. Validators:
   - `scope_subject_id` is set iff `scope == SINGLE_SUBJECT`;
   - `kind == CT` with `scope == SINGLE_SUBJECT` is rejected unless `scope_status == CONFIRMED` **and** `declared_by == "user"` on the latest revision. A circuit CT is never auto single-subject (DEC-05);
   - `valid_until > valid_from` when set.
3. Reuse the existing `LoadShape`, `HaEntityRole`, `MeasurementBasis` enums from `legacy.py` (import them; do not copy).
4. **Naming rule:** nothing in this module may be named with the retired "dedicated" vocabulary (`tests/unit/test_docs_vocabulary.py`, ADR-0034).

## Tests
- One test per HB §1.2 cardinality bullet, built from links:
  - one device → several components;
  - one device → several entities;
  - one device → several endpoints;
  - one reader → many devices;
  - many readers → one device;
  - one entity → several subjects;
  - an endpoint with no HA device.
- Scope validators.
- A legacy id such as `dev_ct_07` is accepted verbatim as `device_id`.
