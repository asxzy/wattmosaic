# M2 — Matrix store, event-driven updater, deterministic reconciler

**Wave:** 4 · **Depends on:** M1, S15, D1 · **Size:** L · **Design:** §8 (update) · **Analysis:** `analysis/E-…` C6, C9, WP-E2 · **Closes:** AT-11

## Objective
- Persist the sparse current matrix and its append-only history.
- Update **only affected cells** per `JointInferenceResult`, counting independent events by group id.
- Bump the mapping version only when a mapping edge changes.
- Run a scheduled, deterministic, audited reconciler that writes SUSPECTED_CHANGE/RETIRED transitions and absorbs new topology or mapping versions.

## Steps
1. `MatrixUpdater.apply(result, operator) -> MatrixDelta`:
   - the affected set = {(subject, reader) | subject in the result's estimates, groups or candidates ∧ reader in rows the subject enters} ∪ group cells;
   - recompute those cells with M1;
   - upsert through S15 in one transaction.
2. Mapping-edge evolution from CONFIRMED matches (I6): a new (subject, reader) association that reaches CONFIRMED proposes a mapping version through `VersionService.propose_mapping` and promotes it. Contribution changes alone never bump the version.
3. `reconcile(reason)` runs on topology or mapping promotion and daily:
   - re-evaluate PROVISIONAL cells;
   - apply SUSPECTED_CHANGE from D1 lifecycles;
   - retire cells whose mapping edge is RETIRED;
   - write an audit row.

   It is idempotent.
4. Port `reconcile_topology_change` ideas from `disaggregation/mapping.py:782-958`, using one version type (`analysis/E-…` T13).

## Tests
- **AT-11:** independent-event counts and confidence rise only with distinct groups. 100 samples from one event change the count by 1.
- HB §17 step 6: only the 6 light×reader cells plus 1 group cell change, and history keeps the old values.
- A plug relocation retires the old cell and creates the new one, while power-model fields keep the same model version.
- The reconciler is idempotent and writes an audit row.
- `cells_as_of(t)` returns the historical state.
