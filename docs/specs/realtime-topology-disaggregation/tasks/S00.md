# S00 — Migration-number seam: version-agnostic schema tests, no backup for fresh databases

**Wave:** 2 (seam; added by the orchestrator after S19 surfaced it) · **Depends on:** X05 · **Size:** S

## Objective
Wave-2 migrations (v013–v020, v025) land in parallel and out of order. Eleven existing tests hard-code `LATEST_VERSION == 11` or require migration numbers 1..N to be contiguous, so any one of them fails the suite. X05's pre-migration backup also fires for a fresh or empty database. Fix both, so that each storage task can merge on its own.

## Owns
- `engine/wattmosaic_engine/storage/database.py` (the backup decision only)
- `engine/wattmosaic_engine/storage/migrations/__init__.py`: add `RESERVED_VERSIONS = frozenset({12})` and `SPARE_VERSIONS = frozenset(range(21, 25))` and export them. Do not change discovery semantics
- `tests/unit/test_app_startup.py`, `tests/unit/test_contracts.py` (only `test_migration_versions_are_sequential`), `tests/unit/test_inference_records.py` (only the fresh-database schema test), `tests/unit/test_migration_discovery.py`, `tests/unit/test_migration_matrix.py`, `tests/unit/test_reconciliation_persistence.py` (only the latest-version test), `tests/unit/test_storage_config.py`

## Steps
1. Every test that asserts a literal latest version must instead assert `== storage.migrations.LATEST_VERSION`, and that a fresh database reaches it.
2. The contiguity rules become:
   - versions 1–11 are contiguous;
   - 12 is never present;
   - every discovered version ≥ 13 is unique and ≤ 25;
   - versions may have gaps above 12, because parallel tasks land in any order and 21–24 are spare.

   Keep the existing "the payload-encoding marker is not a migration" test semantics.
3. `test_migration_matrix.test_matrix_covers_every_prior_version` covers the released versions 9, 10 and 11 (the fixtures that exist) and upgrades each to `LATEST_VERSION`. It must not demand fixtures for versions created in this wave.
4. Backup: skip it when the database file did not exist before `Database.__init__`, when it is empty, or when its `user_version` is 0. Back up only when an existing database with `user_version ≥ 1` has a pending migration ≥ 13. Fix the three failing backup tests accordingly. Keep rotation (newest 3).
5. Prove the seam: add a temporary dummy `v099_seam_probe.py` **only inside a test** (tmp package or monkeypatch, never committed under `storage/migrations/`). The full suite must pass with it discovered.

## Tests
- The full suite is green on the unmodified tree, and green again with a monkeypatched extra migration (v013 and v019 dummies) discovered.
- A fresh database is not backed up. A schema-11 database is backed up once.
