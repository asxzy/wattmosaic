# H2 — HA setup flow v3 (folds in the minimal-ha-setup draft)

**Wave:** 4 · **Depends on:** T4, D2 · **Size:** M · **Decisions:** DEC-05, 06, 10, 13 · **Design:** §11 · **Analysis:** `analysis/A-…` §6 Q5; `analysis/C-…` C6

## Objective
Implement the user's intent from the untracked draft `docs/specs/minimal-ha-setup/`: "only add the CTs, optionally with parent/child; everything else automatic". It is rebased onto 3.0:
- the user declares endpoints and, optionally, parents (as user CONTAINS edges);
- the user can accept a plug's single-subject scope;
- engine-inferred parents are **suggestions** that are written only if the user accepts them;
- there is no silent confirmation of inferred structure (DEC-13).

- `tests/unit/test_config_flow_logic.py`, `tests/unit/test_nesting_wizard.py`, `tests/unit/test_device_links.py`

## Steps
1. The flow:
   - **Connection** (unchanged: URL plus token, or Supervisor discovery).
   - **Endpoints:** list the discovered endpoints (D2). For each CT, an optional parent picker. Engine PROVISIONAL edges are preselected **as suggestions** and labelled; the user must leave them checked to accept. For each candidate plug, "measures exactly one appliance → which device?".
   - **Done:** POST user edges (T4 `POST /topology/edges`) and scope confirmations (D2). No `POST /topology/confirm`.
2. The options flow edits endpoints and parents the same way. The per-device nine-field forms from v2 are removed (devices are automatic, DEC-04).
3. Config-entry migration (`async_migrate_entry`): stored `ct_assignments` become user edges on the next replay. Unknown keys are dropped with a logged notice.
4. Device links (`state_links.py`) write `ha_entity_links` through the v3 API (DEC-08).

## Tests
- No inferred parent is ever posted unless it is user-accepted (assert on the request log).
- A legacy entry migrates and replays without error.
- A plug scope confirm call is made only when the user selects a device.
- The flow works without `homeassistant` installed (pure `flow_logic` tests).
