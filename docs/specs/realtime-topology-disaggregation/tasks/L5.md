# L5 — Per-class incremental learners and promotion v2

**Wave:** 4 · **Depends on:** L2, L3, L4 · **Size:** M · **Decisions:** DEC-32, 34, DEF-03 · **Design:** §9 (class table, promotion) · **Analysis:** `analysis/F-…` C6, WP-F5, §5 T2

## Objective
Each class gets its own incremental update and its own promotion criterion. The candidate and the active version are compared on the **same frozen evidence set**. Promotion needs ≥ 5 independent confirmed events, and a single event never changes an ACTIVE version. This fixes the R² trap that blocks fixed loads (DEF-03).

## Owns
- `engine/wattmosaic_engine/learning/trainer.py`, `learning/validation.py`, `learning/promotion.py`
- new `engine/wattmosaic_engine/learning/incremental.py`
- new `tests/unit/test_incremental.py`, `tests/unit/test_promotion_v2.py`

## Steps
1. Incremental updaters per design §9: P² quantiles, bin-wise PAVA, running state distributions, and robust phase stats.
2. Validation:
   - a time-ordered holdout keyed by observation id (`validation.py:35-53` idea);
   - the per-class criteria from design §9;
   - the evidence-id set is recorded in `PowerModelVersion.evidence_refs`.
3. Promotion:
   - ≥ 5 independent confirmed events, with independence counted by event group;
   - the candidate beats or equals the active version on the frozen set;
   - first version or a class change ⇒ an event flagged "review suggested" (DEC-32), not blocked;
   - frozen ⇒ no promotion.
4. A class-change *proposal* is recorded as a diagnostic suggestion (DEC-34).

## Tests
- **DEF-03 regression:** an all-ON fixed load with MAE 0.3 W promotes.
- A candidate worse on the frozen set is not promoted.
- Incremental and batch fits agree within 2 %.
- A single event never changes an ACTIVE version.
- Freeze blocks promotion.
