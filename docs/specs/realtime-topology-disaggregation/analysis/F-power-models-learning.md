## 3. Reusable assets to keep

- `models/base.py:77-175`: `median`, `quantile`, `robust_sigma` (1.4826·MAD), `_linear_interp` (clamped), PAVA `enforce_monotonic`, `error_metrics`. These are correct, dependency-free building blocks for Fixed and Adjustable.
- `models/device_profile.py`: `AdjustableResponse` (non-linear, monotone optional, any declared control variable, None-not-zero) is the best Adjustable representation and should become the base of the unified learned Adjustable model. `DevicePowerProfile`'s level vocabulary, `operating_w` (transient excluded) and `level_for` lowest-match rule carry over into the new prediction type. `power_after`/`off_w` become a degenerate kernel.
- `models/segmentation.py` (robust change-point segmenter, timestamp-driven, explicit `ambiguous`) and `learning/stages.py` (status from segmentation quality, "never claim a stage you can't distinguish"). Keep both for dynamic-state and kernel phase extraction.
- `learning/validation.py:35-53` (time-ordered holdout) and the fold-stability idea (60-135). Keep these, but key them by evidence id.
- `learning/sample_filter.py`: ordered, deterministic rejection ledger (`_CHECK_ORDER`, `SampleDecision`, rejection persisted with a reason). Extend it with identifiability, residual ambiguity and model consistency rather than rewriting it.
- `learning/pipeline.py:199-259`: isolation evidence via `EventIsolator` with CT-separated competitors. This is the seed of the "event independence" gate input.
- `learning/reporting.py` (`LearningAccounting`, honest `effective_state`): keep it as the learning-status surface.
- `models/registry.py:56-152`: version-keyed LRU cache with per-device failure isolation. Its pattern is right for the atomic model-set swap.
- `learning/promotion.py`: freeze-blocks-promotion semantics, review markers and the never-delete-history rule.
- `aggregation/aggregator.py`: deterministic trapezoidal integration plus gap rule. Keep it, and add version tags.
- `tools/audit/replay_capture.py` production-path replay plus the deadline guard, and `tests/simulation/test_replay_versions.py` fingerprint gate. Extend both with model-version inputs.

## 4. Proposed work packages

File ownership is file-disjoint except for the shared hot files named in each WP. `contracts.py`, `storage/migrations.py` and `storage/database.py` belong to the domain/storage agent. Area F supplies **schemas and method specs** for them and does not edit them in parallel.

### F1. Power-model contract, codec and registry v2 (L)
- **Objective:** a canonical versioned `PowerModel` (subject = device | component; `model_class`; `basis` = DELTA | ABSOLUTE_ANCHOR; `levels{standby, idle, active, transient}` each `{median, mad, n}`; class payload; `schema_version`; `evidence_refs`; `topology_version_at_training`; `trainer_version`; `parent_version`). Lossless codec. One active version per subject. Append-only versions plus a status-event log. Rollback reactivates the last version whose log shows ACTIVE. Retire the parameter-only interpreter in `electrical/models.py:127-170` in favour of `registry.predict()`.
- **Owns:** `models/serde.py`, `models/registry.py`, new `models/spec.py`, `models/prediction.py` (`PowerPrediction{level, mean_w, sigma_w, status}`).
- **Shared (spec only, applied by the domain/storage agent):** `contracts.py` (`DeviceModelVersion` → `PowerModelVersion`, `DeviceModelParameters` retired), `storage/migrations.py` (new `power_model_versions`, `power_model_events`, legacy `device_model_versions` frozen read-only and flagged `semantics=legacy_absolute`), `storage/database.py` model methods. `electrical/models.py` is touched jointly with the matching/inference agent.
- **Depends on:** domain agent for `LoadComponent` ids and `EvidenceReference`; topology agent for the `TopologyVersion` id type.
- **Tests:** round-trip property test for every class (`decode(encode(m))` predicts identically on a context grid), with explicit regressions for composite/component sum, the adjustable `control_variable` and the kernel. A rollback test that never reactivates a REJECTED or never-active version. A test that one active version exists per subject across a class change. A legacy-row migration test (rows readable, flagged, never served as validated).

### F2. Fixed and Adjustable model classes on a delta basis (M)
- **Objective:** `FixedPowerModel`: standby, idle, active and transition ΔP, each as median plus 1.4826·MAD with counts. Standby comes from exclusive-anchor `P_old`, or from ΔP plus a residual-baseline step when not anchored. OFF is never 0 W unless measured. `AdjustableModel`: unify dimmable, variable-speed and `AdjustableResponse`. Use the declared control variable (no hard-coded vocabulary, no `_MAX_RPM`), monotone only if declared or validated, and an x-coverage report. Fit P(x) − standby via ΔP between levels.
- **Owns:** `models/binary.py` → `models/fixed.py`, `models/dimmable.py` + `models/variable_speed.py` → `models/adjustable.py`, `models/base.py` (remove `OFF_STATES_DEFAULT` idle/standby collapse and `or 0.0` fallbacks), `models/device_profile.py` (declared priors become a `prior` on the same spec).
- **Depends on:** F1 types; F4 observations.
- **Tests:** AT 3 (a 7 W standby on a *shared* circuit, learned from ΔP plus anchor, survives an OFF transition with `level=STANDBY` and `mean≈7`, never 0). A non-linear adjustable curve recovered without assuming P=kx. Unknown level returns `None`/`UNKNOWN`. A MAD-based variability check against an inrush outlier.

### F3. Dynamic and Component models plus response kernels (L)
- **Objective:** (a) `DynamicStateModel`: hidden operating states per HA state (e.g. "cool" maps to {fan-only, compressor}). Includes a transition-count matrix, per-state duration distributions and state-conditioned power distributions, initialised by segmentation and updated incrementally. (b) `ResponseKernel` `h(τ | transition, attrs)` with phases startup / active / steady / shutdown / standby. Each phase has a delay distribution, an amplitude distribution and a duration. Kernels are keyed by transition type (on→off, open→close, mode change). They are learned from aligned event windows and exposed as `expected_window(transition, attrs, τ_grid) -> (mean, sigma)` for matching (HB §7.3). (c) `ComponentSum`: a device model is the sum of component models; an HA entity can drive several components with separate kernels (HVAC fan vs compressor).
- **Owns:** `models/multi_state.py` + `models/time_varying.py` → `models/dynamic.py`, new `models/kernel.py`, `models/composite.py` → `models/components.py`, `models/segmentation.py`, `learning/stages.py`.
- **Depends on:** the pipeline agent's EventGroup with per-endpoint pre/post window series aligned to the transition; the domain agent's LoadComponent + HAEntity↔Component bindings; the matching agent consumes the `expected_window` interface (agree its signature early).
- **Tests:** AT 5 support (the kernel separates a 0 s lamp, a 20 s HVAC compressor delay and a blind's transient-then-standby). A fridge cycle yields ≥ 2 states under one HA state. A component sum predicts fan + compressor with separate delays. The kernel round-trips through the F1 codec.

### F4. Learning evidence intake and quality gate v2 (M)
- **Objective:** replace collector-built absolute samples with `LearningObservation` derived from **immutable** EventGroup plus joint-inference assignment. Use a deterministic id = hash(event_group_id, subject_id, endpoint_id, topology_version). Gate inputs: measurement quality; association posterior; topology-version validity (no `SUSPECTED_CHANGE` on the relationship used); model consistency (observation vs active model predictive interval); **identifiability** (must be individually identifiable, else the observation is attributed to the group model only); **event independence** (from isolator plus event group); **residual ambiguity** (unknown-load posterior below threshold). Observations are `PROVISIONAL` or `CONFIRMED`; only confirmed ones update confirmed models, and provisional ones are retained.
- **Owns:** `learning/sample_collector.py` (becomes an observation builder), `learning/sample_filter.py`, `learning/thresholds.py`, `learning/pipeline.py` (intake half), `learning/reporting.py`.
- **Shared:** `contracts.py` (`LearningSample` → `LearningObservation`, spec via the domain agent); `integration.py:_bridge_event` must keep `event_id` (coordinate with the pipeline agent).
- **Depends on:** the pipeline agent (EventGroup ids, windows, quality); the matching/joint-inference agent (assignment posterior, identifiability status, unknown-load posterior); the topology agent (relationship status per version).
- **Tests:** each new rejection reason is reachable. A non-identifiable pair produces group-model evidence and no per-device update (AT 7 learning side). The same event replayed twice produces the same observation id. An observation from a relationship in `SUSPECTED_CHANGE` is held PROVISIONAL.

### F5. Per-class incremental learners and promotion v2 (M)
- **Objective:** incremental updaters per class: Fixed uses windowed or P²-quantile robust median/MAD; Adjustable uses incremental isotonic regression (PAVA on bins); Dynamic uses state-conditioned running distributions plus transition counts; Kernel uses robust running phase estimates. Per-class acceptance criteria (C6). Candidate and active are compared on the same **frozen** evidence-id set recorded in the version. Promotion cannot happen from fewer than N independent confirmed events (independence counted per event group, not per sample). Fix the R² trap.
- **Owns:** `learning/trainer.py`, `learning/validation.py`, `learning/promotion.py`, new `learning/incremental.py`.
- **Depends on:** F1, F2/F3 class APIs, F4 observations.
- **Tests:** an all-ON fixed load with MAE 0.3 W promotes (regression of T2). A candidate worse on the frozen set is not promoted. Incremental vs batch agree within tolerance. A single event never changes an ACTIVE version's parameters.

### F6. Background learner off the event loop (S-M)
- **Objective:** move `_maybe_train` and model-version replay out of `WattMosaicBackend.process`. The fast path enqueues `(subject_id, observation_ids)`, and a worker (`asyncio.to_thread` or a dedicated thread with a bounded queue, per the ADR-0033 precedent) trains, validates, promotes and swaps the registry cache. Use a per-subject dirty set instead of scanning all topology devices each cycle (integration.py:690-700). Restart-safe: dirty set re-derived from unconsumed confirmed observations (HB §15 "no hidden in-memory state").
- **Owns:** new `learning/worker.py`; the learning part of `integration.py` (`_learn`, `_maybe_train`, `learning_status`).
- **Shared hot files:** `integration.py` (pipeline agent owns `process`/events; agree a single hook `on_confirmed_evidence(...)`), `main.py` (worker start/stop in `start()` and shutdown).
- **Tests:** `test_training_runs_off_the_event_loop` (health probe latency during a forced 2 s training stays < 100 ms, modelled on ADR-0033 tests). A cycle with no new confirmed evidence costs zero DB queries for learning. Worker crash or restart loses no evidence.

### F7. Historical reconciliation and versioned replay (L)
- **Objective:** a `Reconciler` that replays **immutable** evidence (EventGroups, EventEvidenceRecords, retained windows and aggregates) with an explicit `(power_model_version_set, topology_version)` and writes derived outputs (inference records, matrix-cell inputs, energy buckets) into a **versioned derived namespace**. It never touches measurements or evidence. Triggers: new model version promoted, topology version promoted, late evidence. Old derived outputs are kept and marked superseded. `replay_capture.replay(..., models=ModelSet)` takes a model set. Energy buckets and device runs get `model_set_id`/`topology_version` columns.
- **Owns:** new `learning/reconciliation.py` (or `replay/`), `tools/audit/replay_capture.py`, `tests/simulation/test_replay_versions.py`, `aggregation/aggregator.py`, `aggregation/models.py`, `aggregation/repository.py`.
- **Shared:** `disaggregation/audit.py:reanalyze` (pipeline/topology agents) should become a *client* of the Reconciler or stay audit-only; decide ownership. Storage schema for the derived namespace (domain/storage agent).
- **Depends on:** the pipeline agent's evidence being replay-sufficient after raw expiry (HB §15); the joint inference engine callable as a pure function of (evidence, models, topology); the matrix agent's consumption of versioned derived outputs.
- **Tests:** **AT 19**: replay a week of evidence with model v1 and v2. Derived outputs differ as expected, raw `ct_samples`/evidence are byte-identical before and after, and both result sets are retrievable by version. **AT 15**: plug relocation creates a new topology version; replay under the new topology changes mapping cells while the power-model version id is unchanged and its parameters are within tolerance. Determinism gate extended with the model-set fingerprint.

### F8. Active-learning suggestions (S, optional)
- **Objective:** a read-only ranked list of suggested user actions from identifiability groups and kernel/standby uncertainty (e.g. "toggle Light A alone"). Scoring uses uncertainty × expected identifiability gain × measurement impact ÷ user effort, with a safety class. The system never calls HA services.
- **Owns:** new `learning/suggestions.py`, an API read endpoint (coordinate with the UI agent).
- **Depends on:** identifiability groups from the joint-inference agent.
- **Tests:** two always-co-switched lights produce a "test independently" suggestion. A static test asserts no code path issues a `call_service`.

Suggested order: F1 → (F2 ∥ F4) → F3 → F5 → F6 → F7 → F8. F6 can start after F1 because it only moves existing calls.

## 5. Traps and constraints

- **T1 (verified): composite rehydration loses sub-models.** Probe: a fitted composite predicts 100.5 W; `build_model(COMPOSITE, m.parameters)` predicts **0.0 W, confidence 0.0**. `registry.model_for` and `promotion.validate` both rehydrate this way (registry.py:129, promotion.py:93). Similarly, `DimmableDeviceModel.control_variable` is not persisted (dimmable.py:86, 104). A model trained on `brightness_pct` reloads as `"brightness"`, and `_normalise_control` then scales a `brightness_pct` query by 2.55× against a pct-keyed curve. `BinaryDeviceModel.notes` (spread) is lost, so live and reloaded confidence differ. F1's lossless codec must land before any new class.
- **T2 (verified): fixed loads cannot promote.** An 8-sample all-ON holdout (60–61 W): R² = −0.026, MAE = 0.31 W. With `min_validation_r2 = 0.70` (thresholds.py:107) every well-behaved fixed load is stuck at `manual_review_required`. Any "realtime learning works" claim from e27f5c4 should be re-checked against promoted counts in a real DB.
- **Serde compatibility of persisted models:** existing `device_model_versions` rows are absolute-basis and possibly whole-row credited. HB §16.6-7: they must **not** be silently reinterpreted. Recommend keeping them read-only, flagged `legacy_absolute`, not served as validated power. They may seed priors only on exclusive anchors. Migration and rollback must keep the old table intact (the migration-matrix test exists: `tests/.../test_migration_matrix.py`).
- **Promotion state machine:** today `INSERT OR REPLACE` mutates rows and rollback can reactivate a rejected candidate (database.py:1374-1392). Fix this in F1 *before* auto-promotion volume grows. Freeze semantics (frozen blocks promotion, not inference, registry.py:157-159) are a product contract and must be kept.
- **Perf off the loop:** today any matured sample triggers `stored_samples` plus `versions` for **every** topology device inside the 5 s inference loop (integration.py:690-700), followed by a full refit and synchronous reanalysis over up to 2000 events plus a CT history read (integration.py:895, audit.py:957-969). On a Pi with ~40 devices and weeks of samples this will reproduce the ADR-0033 outage. `learning_samples` is L4 and never pruned (storage/tiers.py:100), so refit cost grows without bound. F5's incremental updates plus F6's worker are required, and refits must be bounded by window or count.
- **Thread safety:** `Database` uses one connection with `check_same_thread=False` and an RLock. A worker thread is acceptable (ADR-0033 precedent), but long write transactions from training must not starve the writer loop. Batch the writes.
- **Determinism for replay:** `uuid4` sample ids (sample_collector.py:361), `utcnow()` defaults (contracts `created_at`, pipeline.py:212, 416) and holdout split dependence on the current sample set break replay identity. Use content-derived ids and an injected clock.
- **Cross-type identity:** a class change creates a second `device_models` row. `active_model(device_id)` without a type picks by `created_at` (database.py:1334-1338). Until F1 lands, the class must not flip silently (C8).
- **Declared vs learned universes:** declared `DevicePowerProfile` (configuration.py:187-205, engine.py:1740) and learned `DeviceModelVersion` never meet today. F2 must define precedence (Q3) or inference will publish two different "standby" values.
- **Stale tracker:** `docs/specs/load-disaggregation/tasks/progress.md` marks TASK-POWER-003/004 `VERIFIED`. Those cover the **declared** profile only; the learned models gained nothing, and TASK-LEARNING-001/002 are `NOT_STARTED`. Do not cite them as delivered learned behaviour.

Interfaces Area F needs from other agents:
- **Domain/contracts/storage:** `PhysicalDevice`, `LoadComponent` (ids, HA-entity↔component many-to-many), `EvidenceReference`, `TopologyVersion` id, migration framework, and the derived-output namespace schema.
- **Real-time pipeline:** immutable `EventGroup{id, transition(s), endpoints, pre/post window series aligned to τ=0, quality, other-events-in-window}`, replay-sufficient after raw expiry; a "confirmed evidence" hook; `event_id` preserved through `_bridge_event`.
- **Topology + residual:** relationship status per version (`SUSPECTED_CHANGE`), configuration events, exclusive-anchor flag per (endpoint, subject), residual baseline step events (for standby on shared circuits).
- **Matching + joint inference:** per-event assignment posterior per candidate including unknown load; identifiability status and group membership; the inference engine as a pure function `(evidence, model_set, topology_version) -> outputs` for F7. Area F supplies `PowerPrediction` and `ResponseKernel.expected_window` to them.
- **Matrix + UI:** consume versioned derived outputs and model version, evidence-used and suggestion read models.

## 6. Open questions for the product owner

1. **Legacy models:** should existing absolute-basis learned models be (a) kept read-only and flagged legacy while models are retrained from delta evidence (recommended), (b) used as priors, or (c) discarded?
2. **Auto-promotion:** may a learned model be promoted automatically, or must the first version per subject (or any class change) wait for user approval?
3. **Declared vs learned:** when a user-declared standby/active/curve disagrees with learned evidence, which is published? Does learning ever overwrite a declaration, or does it only raise a discrepancy?
4. **Model class:** is the class strictly the declared `LoadShape`, or may learning propose (never apply) a different class?
5. **Load Components:** user-declared only, or may learning discover components (fridge compressor vs defrost heater) and propose them?
6. **Reconciliation reach:** when replay with a newer model changes past derived energy, should the HA long-term statistics/energy entities be corrected, or only the engine's internal versioned views (HA statistics are effectively append-only)?
7. **Evidence retention budget:** how long are full event windows retained for kernel learning and replay (HB §15), and what disk budget is acceptable on a Pi?
8. **Active learning (F8):** in scope for this release or deferred? If in scope, are suggestions that involve safety-relevant loads (HVAC, garage door) allowed or suppressed?
9. **Compute budget:** what is the acceptable background-learning CPU budget and maximum latency from confirmed evidence to promoted model ("realtime" per e27f5c4 vs bounded batches)?
